# Полный гайд: iSCSI-диск на Mac и обмен с Windows

Приложение, его исходный код и этот гайд созданы при помощи **Codex и ChatGPT (OpenAI)** в совместной работе с автором проекта.

Версия приложения: **0.4.2, экспериментальная**. Проверено на Apple M4, macOS 27.0.1 и Synology DS220j. Готовый ZIP предназначен для Apple Silicon. Другие Mac и версии macOS требуют отдельной проверки. Интерфейс доступен на русском и английском.

[English guide](GUIDE_EN.md)

Приложение использует стандартный протокол iSCSI и не привязано к Synology. Подключение к другим NAS и серверам с iSCSI Target предполагается, но пока не проверено: совместимость зависит от возможностей Target и ограничений приложения. Фактические проверки выполнены только с Synology DS220j. Ниже Synology приведён как пример настройки.

## 1. Что вы получите

LUN — виртуальный блочный диск, выделенный на NAS или сервере. iSCSI передаёт команды чтения и записи по сети. Target — точка подключения с именем IQN; к ней привязаны один или несколько LUN с числовыми адресами.

Приложение превращает LUN в виртуальный диск macOS. Том с поддерживаемой файловой системой появляется в Finder, и приложения работают с файлами обычным способом. Данные остаются на NAS или сервере. Полный образ LUN на Mac не скачивается.

В «Дисковой утилите» транспорт будет **Disk Image**, поскольку используется встроенная инфраструктура дисковых образов поверх приватного локального моста. Это не собственный SCSI-драйвер. NFS на NAS или сервере включать не требуется.

## 2. Подготовка

Понадобятся адрес NAS / сервера, доступ к его iSCSI-порту (обычно TCP 3260), Target IQN, номер LUN и при включённом CHAP — отдельные имя и пароль CHAP. Пароль администратора сервера для входа в iSCSI не используется.

Для первых опытов создайте отдельный пустой LUN. Это экспериментальное ПО, без квалификации для единственной копии важных данных. Приложение не блокирует параллельное использование LUN другим компьютером.

**Обычные APFS и exFAT нельзя одновременно монтировать на Mac и Windows через один LUN.** Один компьютер должен полностью освободить диск до подключения второго. Это относится и к автоматическому подключению при пробуждении или запуске ОС.

Используйте доверенную локальную сеть либо уже настроенный VPN. Приложение само не включает VPN, не шифрует iSCSI-трафик и не требует публикации порта NAS в интернет. CHAP проверяет знание секрета, но не шифрует содержимое диска.

## 3. Создание Target и LUN (пример Synology)

На другом сервере включите iSCSI Target, создайте LUN, привяжите его к Target и разрешите доступ с Mac. Запишите адрес, порт, IQN, номер LUN и параметры CHAP, если они нужны. Названия разделов зависят от производителя.

На Synology в DSM 7 откройте **SAN Manager**:

1. В разделе **LUN** создайте пустой LUN, задайте понятное имя, размещение и размер.
2. В разделе **iSCSI** создайте Target либо выберите существующий. Запишите его полный IQN.
3. Привяжите LUN к Target и уточните назначенный номер LUN. Имя LUN и его номер — разные значения; номер не обязательно равен 0.
4. При необходимости настройте односторонний CHAP и права доступа инициатора. Приложение не поддерживает Mutual CHAP. Оно использует IQN инициатора `iqn.2026-10.local.synologyinitiator:mac`; значение пока общее, отдельного редактора IQN в интерфейсе нет. Windows использует собственный IQN, показанный в настройках своего инициатора.
5. Убедитесь, что LUN исправен и для него хватает места на NAS. Для LUN с тонким выделением следите также за свободным местом тома NAS.

Названия разделов зависят от DSM; в DSM 6 используется iSCSI Manager. Подробности и ограничения модели см. в [официальной инструкции Synology](https://kb.synology.com/en-my/DSM/tutorial/How_to_use_the_iSCSI_Target_service_on_Synology_NAS_7).

Если настроено ограничение доступа по IQN, разрешите соответствующий инициатор. Наличие Target в поиске само по себе ещё не означает разрешение чтения LUN.

## 4. Установка приложения

### Готовая сборка

1. Откройте [Releases](https://github.com/Kamradi/macOS-iSCSI-Initiator/releases).
2. Скачайте `macOS-iSCSI-Initiator-0.4.2-macos-arm64.zip` и `SHA256SUMS.txt`.
3. При желании сравните SHA-256 архива командой `shasum -a 256 ИМЯ_АРХИВА.zip` с опубликованным значением. Совпадение подтверждает соответствие архиву, но не является подписью доверенного издателя.
4. Распакуйте ZIP. Перенесите `SynologyInitiator.app` в «Программы» или другую постоянную папку и запустите.

Сборка подписана ad-hoc и **не нотариально заверена Apple**. На другом Mac загруженное приложение может быть заблокировано. Проверяйте источник и содержимое выпуска; инструкции Apple по открытию доверенного непроверенного приложения находятся [здесь](https://support.apple.com/en-hk/102445). Самостоятельная сборка из проверенных исходников — альтернативный путь. Не отключайте SIP или Gatekeeper целиком. Прохождение предупреждений macOS на чистом другом Mac не проверялось.

Если macOS запросит доступ к локальной сети, разрешите его для подключения к вашему NAS.

### Сборка из исходников

Нужны Xcode и Swift 6. Использовавшаяся при разработке версия Swift — 6.4. Сборка пакета командными инструментами других версий отдельно не проверена.

```sh
git clone https://github.com/Kamradi/macOS-iSCSI-Initiator.git
cd macOS-iSCSI-Initiator
zsh build-app.sh
swift test
python3 scripts/check-localization.py
```

Откройте `dist/SynologyInitiator.app`. Эта команда не устанавливает системный драйвер и не форматирует диски.

## 5. Первое подключение

В поле **Язык / Language** выберите **Системный / System default**, **English** или **Русский**. Настройка сохраняется и применяется сразу, в том числе к текущим статусам и меню. Системный вариант использует русский при первом предпочтительном языке macOS ru, иначе английский. Системные диалоги и ошибки штатных утилит могут оставаться на языке macOS. Уже запущенный мост сохраняет язык своих технических журналов до следующего подключения; смена языка интерфейса не отключает диск.

| Поле | Что указать | Учебный пример |
| --- | --- | --- |
| Адрес NAS / сервера | IP или DNS-имя, доступное с Mac | `nas.example.net` |
| Порт | iSCSI TCP-порт NAS | `3260` |
| Target IQN | Полное имя Target из панели управления сервером | `iqn.2026-10.example:storage.target1` |
| LUN | Числовой адрес LUN, привязанного к Target | `0` |
| Авторизация CHAP | Включить, если её требует Target | выключена / отдельное имя и секрет |

Примеры выше — заглушки, их необходимо заменить своими значениями.

1. Заполните адрес и порт.
2. Нажмите **Найти Target**, затем выберите нужный результат. Можно вставить IQN вручную. Если discovery с CHAP не поддерживается NAS, отключите CHAP для поиска, затем включите обратно перед подключением к известному IQN.
3. Введите номер LUN. Кнопка поиска Target не определяет номер LUN автоматически.
4. При необходимости заполните CHAP. Пароль хранится только в памяти и после перезапуска приложения вводится снова.
5. При желании нажмите **Проверить LUN** — это диагностика доступности, без форматирования и записи пользовательских файлов.
6. Нажмите **Подключить диск**. Эта кнопка также включает автоподключение. На проверенной конфигурации подключение занимает около минуты.
7. Если файловая система распознана, появится **Открыть в Finder**. Если диск пустой — перейдите к следующему разделу.

Настройки сохраняются локально. Закрытие окна не завершает приложение: управление остаётся в строке меню.

При выборе другой цели в списке Target автоподключение приостанавливается. Проверьте номер LUN: у разных Target номера могут различаться. Приложение проверит привязку перед подключением и укажет доступные LUN, если номер неверен. Смена Target недоступна, пока диск подключён.

## 6. Форматирование

**Форматирование полностью удаляет данные выбранного диска.** Не ориентируйтесь только на номер `diskN`: macOS меняет номера после переподключений. Сопоставьте устройство, указанное приложением, размер LUN и выбранный внешний виртуальный диск. Не выбирайте Macintosh HD или физические диски Mac.

1. Подключите нужный LUN только с Mac.
2. Откройте **Дисковую утилиту → Вид → Показать все устройства**.
3. Выберите весь виртуальный диск этого LUN, а не посторонний том.
4. Нажмите **Стереть**. Для современной пары Mac/Windows используйте схему **GUID** и **ExFAT**; только для Mac можно выбрать **APFS**. Назовите том, например `ISCSI`.
5. Дождитесь полного завершения. Не закрывайте крышку и не отключайте сеть во время форматирования.

[Apple перечисляет exFAT как формат, совместимый с Windows](https://support.apple.com/en-ie/guide/disk-utility/dsku19ed921c/mac). Это не позволяет одновременно работать с одним LUN с двух компьютеров. APFS без дополнительного ПО Windows не читает.

Реальные проверки этого приложения выполнялись с APFS. Сквозной сценарий exFAT ↔ Windows пока не проверялся, поэтому сначала проведите собственную проверку на пустом тестовом LUN. APFS нельзя превратить в exFAT без переформатирования: сохраните файлы в другое место заранее.

## 7. Mac и Windows по очереди

### Передать LUN с Mac на Windows

1. Закройте файлы и приложения, использующие том на Mac.
2. В приложении нажмите **Извлечь диск**. Дождитесь сообщения об успешном извлечении. При этом автоподключение выключается.
3. Убедитесь, что Mac больше не держит iSCSI-сессию к этому LUN; это можно проверить в панели управления сервером (на Synology — SAN Manager).
4. Только после этого подключайте Windows.

Отдельных кнопок «Передать Windows» и «Вернуть на Mac» в этой версии нет.

### Подключение Windows

1. Откройте встроенный **Инициатор iSCSI** (`iscsicpl.exe`). При необходимости запустите предложенную службу.
2. Введите адрес NAS и подключите нужный Target. Если нужен CHAP, задайте его в расширенных параметрах подключения.
3. Для поочерёдного использования с Mac не оставляйте автоматическое восстановление этого Target на Windows: проверьте список избранных/постоянных подключений.
4. Откройте **Управление дисками** (`diskmgmt.msc`). Найдите диск по размеру и разделам.
5. Если на LUN уже есть exFAT, не инициализируйте и не форматируйте его заново. При необходимости назначьте букву существующему тому.

Для администраторов альтернатива — PowerShell от имени администратора, без CHAP в этом примере:

```powershell
Start-Service MSiSCSI
New-IscsiTargetPortal -TargetPortalAddress 'nas.example.net' -TargetPortalPortNumber 3260
Get-IscsiTarget
Connect-IscsiTarget -NodeAddress 'iqn.2026-10.example:storage.target1' -IsPersistent $false
```

Команды из официальной документации Microsoft: [создание портала](https://learn.microsoft.com/en-us/powershell/module/iscsi/new-iscsitargetportal), [подключение Target](https://learn.microsoft.com/en-us/powershell/module/iscsi/connect-iscsitarget). Замените учебные адрес и IQN своими. Команды не форматируют диск.

### Вернуть LUN с Windows на Mac

1. Завершите копирование, закройте все файлы на Windows.
2. Безопасно отключите том штатным способом Windows; если обычное извлечение недоступно, переведите именно этот диск Offline в «Управлении дисками» после закрытия файлов.
3. Отключите Target в инициаторе iSCSI. Не ограничивайтесь закрытием окна программы. В PowerShell можно использовать `Disconnect-IscsiTarget -NodeAddress 'ВАШ_IQN'`; команда запрашивает подтверждение. [Документация Microsoft](https://learn.microsoft.com/en-us/powershell/module/iscsi/disconnect-iscsitarget).
4. Убедитесь, что постоянное подключение Windows не включит сессию снова.
5. На Mac нажмите **Подключить диск**. Проверяйте файлы, затем продолжайте работу.

Сон Mac не является передачей владения Windows: если автоподключение на Mac осталось включённым, после пробуждения он может подключить LUN снова. Для передачи всегда используйте явное извлечение и отключение автоподключения.

## 8. Сон, работа вне дома и VPN

Оставьте приложение работать в строке меню и включите автоподключение.

- Перед обычным сном приложение прекращает новые подключения и пытается безопасно извлечь диск.
- После пробуждения без доступа к NAS оно ждёт, не подключает VPN и не создаёт новый недоступный том.
- При возвращении доступа начинается переподключение. Неудачные попытки повторяются с интервалами 15, 30, 60 и затем 120 секунд.
- Если вы нажали **Извлечь диск**, повторные подключения прекращаются до вашего явного включения.
- После неопределённого I/O или неуспешного извлечения автоматическое монтирование блокируется. Закройте файлы и повторите извлечение; при незавершённом подключении используйте **Проверить прежнее подключение**.

macOS разрешает лишь ограниченное время на подготовку ко сну. При занятом томе, большой записи или уже оборвавшейся сети извлечение может не завершиться. Закрытие крышки под нагрузкой, обрыв питания и принудительное завершение процесса не превращаются в гарантированно безопасные операции. Автозапуск при входе в macOS не установлен.

## 9. Новые LUN

Программа поддерживает **один сохранённый профиль и один подключённый LUN**.

Чтобы переключиться: извлеките текущий диск, измените адрес/Target/LUN, при необходимости CHAP и нажмите подключение. Предыдущий профиль будет заменён. Для нескольких независимых дисков создайте соответствующие LUN/Target на NAS, но подключайте их в этой версии по одному.

Номер LUN можно проверить консольной диагностикой:

```sh
dist/iscsi luns nas.example.net iqn.2026-10.example:storage.target1
```

## 10. Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Target не найден | Адрес, маршрут/VPN, TCP 3260, служба iSCSI и права discovery; попробуйте известный IQN вручную |
| Вход отклонён | Полный IQN, CHAP, права инициатора, необходимость отключить Mutual CHAP |
| LUN отсутствует | Его числовой номер, состояние и привязку к выбранному Target |
| Диск есть, тома в Finder нет | Новый диск может быть пустым; существующая файловая система может не поддерживаться. Не соглашайтесь на стирание, если нужны данные |
| Windows просит инициализировать диск | Убедитесь, что это правильный LUN и что он содержит совместимую систему. APFS не становится exFAT от подключения к Windows |
| Извлечение не удалось | Закройте документы, окна терминала с текущей папкой на томе, фоновые операции и приложения; повторите |
| После обрыва всё ещё виден том | Он может быть offline. Не продолжайте запись, не запускайте второй инициатор поверх него; сначала извлеките прежнее подключение |
| После ручного извлечения диск не возвращается | Это намеренно: включите автоподключение или нажмите подключение |
| После перезапуска не проходит CHAP | Пароль специально не сохранён; введите заново |
| Подключение/форматирование медленное | Прототип обслуживает команды последовательно и подтверждает записи после flush; оценка максимальной скорости не проводилась |

Не выполняйте автоматически найденные команды стирания `/dev/diskN` и принудительного извлечения без проверки устройства. Если неясно, что происходит, остановитесь и сохраните логи для диагностики.

## 11. Диагностика и сборка

Язык хранится в настройках macOS для приложения отдельно от профиля NAS. Для консольной диагностики можно задать `ISCSI_LANGUAGE=en` или `ISCSI_LANGUAGE=ru`.

Папка настроек: `~/Library/Application Support/SynologyInitiator/`.

- `profile.json`: последний профиль, автоподключение, признак незавершённого отключения; без пароля.
- `active.json`: принадлежность текущего подключения и пути локального моста.
- `lifecycle.log`: события сна, пробуждения и подключения.
- Каталоги отдельных сессий: `ready.json` и `bridge.log`.

Даже без паролей эти файлы могут содержать приватные адреса, IQN, имена пользователя, пути и локальные идентификаторы. Не публикуйте их целиком. Для отчёта укажите версию приложения/macOS/DSM, модель Mac/NAS, последовательность действий и очищенный текст ошибки. Не присылайте данные LUN.

Консольные команды для чтения:

```sh
dist/iscsi discover nas.example.net
dist/iscsi luns nas.example.net iqn.2026-10.example:storage.target1
dist/iscsi inspect nas.example.net iqn.2026-10.example:storage.target1 0
dist/iscsi readcheck nas.example.net iqn.2026-10.example:storage.target1 0
```

Не запускайте дополнительные диагностические сессии к LUN, которым уже пользуется приложение. CHAP в консоли берётся из `ISCSI_USERNAME` и `ISCSI_PASSWORD`; для обычной работы удобнее GUI. Не вводите секрет в команду, которая останется в истории терминала.

В исходниках есть отдельная команда `writecheck`, разрешаемая переменной `ISCSI_ALLOW_WRITE_TEST`. Она временно перезаписывает участок LUN и при ошибке может не восстановить его. **Она предназначена только для разработчиков на одноразовом тестовом LUN, не для проверки диска с файлами.** Команды моста с `--read-write` тоже предоставляют запись; не запускайте их вручную параллельно с приложением.

## 12. Удаление

1. Закройте файлы на томе и нажмите **Извлечь диск**.
2. Убедитесь, что операция завершена, затем завершите приложение через строку меню.
3. Удалите `.app` и при необходимости исходники/архивы.
4. Папку настроек можно удалить после подтверждения отсутствия активного диска и моста. Не удаляйте служебные файлы, пока подключение работает.

Удаление приложения не удаляет LUN или его данные на NAS. Удаление LUN в DSM — отдельная разрушительная операция.
